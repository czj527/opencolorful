# OpenColorful 项目定位与开发路线

> 更新日期：2026-08-22
>
> 本文是 OpenColorful 产品定位、阶段路线和长期边界的权威文档。README 只保留面向公开读者的摘要；当前工作状态以 docs/project-status.md 为准。

## 一、当前定位

OpenColorful 是一个**本地优先的个人助理 Agent 平台与个人效率工作台**。

近期目标不是让 Agent 立刻拥有“完整的一生”，而是先把一个真正好用、可控、可持续的个人助理 Agent 做完整：它能够帮助用户处理信息、文件、任务和日常工作；同时，用户和 Agent 可以在同一个工作台里管理项目、资料与日程。

“给 Agent 完整的一生”仍然是远期愿景，不是当前版本的产品承诺。API 成本、模型可靠性、自动化安全和用户心智都还在沉淀，当前优先级是可用、可控、可恢复。

## 二、产品结构

### 1. 个人助理 Agent

这是近期最重要的产品目标。Agent 应该能够：

- 记住经过确认的用户信息和工作上下文；
- 处理文件、工作目录、文本和常见办公任务；
- 使用受控工具完成检索、整理、执行和反馈；
- 通过 Skill 和 Plugin 扩展能力；
- 在需要时执行后台任务、提醒和有限的主动行为；
- 在多个会话中保持清晰、可迁移、可审计的状态。

Openhanako 是这一层的主要产品参考。我们先对标其已经验证的个人助理体验，再根据本项目的工程基础和用户工作流形成差异化。

### 2. 人与 Agent 共用的工作台

这是 OpenColorful 的核心差异化方向。

- Agent 有自己的会话、记忆、任务和工作空间；
- 用户有自己的项目、任务、笔记和日程；
- 项目可以关联 Agent、会话、文件、任务和运行记录；
- 日程以日历或日程表呈现，而不仅是聊天里的提醒；
- 用户可以查看 Agent 正在做什么、为什么这样做，以及下一步需要什么；
- Agent 的结果能够回到项目和日程中，而不是停留在聊天记录里。

平台不只承担 Agent 平台的工作，也承担个人效率平台的工作。用户和 Agent 是工作台中的两个同级参与者。

### 3. 生态与自扩展

中期建设 Plugin、Skill、角色卡、外部平台连接和更成熟的 Subagent 能力。

更远期研究 DeepSeek Harness 提出的 Cordis 化方向，让 Agent 在约束、审查、测试、安装和回滚机制下，为自己编写插件、技能和工作流。

这条路线可能要求重新设计 Runtime、Plugin、Skill、沙箱、权限快照和工作台之间的边界。它不是近期功能，也不会通过简单提高模型权限来实现。

## 三、与 openhanako 的关系

openhanako 是我们的主要产品参考，尤其是在以下方面：

- 面向普通用户的个人助理定位；
- 人格和记忆带来的连续体验；
- 书桌、文件、定时任务和有限主动行为；
- Skill、Plugin 和多 Agent 能力；
- Electron 桌面端与完整图形界面。

OpenColorful 不把自己定位成 openhanako 的复制品，而是采用“先对标，再差异化”的路线：

| 方向 | 参考重点 | OpenColorful 的计划 |
|---|---|---|
| 个人助理 | 人格、记忆、工具、书桌、自动化 | 先补齐可用的个人助理垂直切片 |
| 工程基础 | 运行时、权限、数据和恢复 | 保留 Server-first、契约、Replay、沙箱和审计 |
| 工作台 | Agent 的会话和工作空间 | 增加用户同级的项目、任务、资料和日程 |
| 扩展能力 | Skill、Plugin、Bridge | 采用受控快照和来源治理，逐步开放生态 |
| 自我演进 | Agent 主动学习或编写能力 | 作为远期 Cordis 化研究，不提前承诺 |

## 四、当前现实边界

当前项目已经具备较完整的平台底座，但还不能把底座规模等同于完整的个人助理产品。

已经具备：

- Server、Session、Provider 和 Supervisor；
- Agent 身份、人格底色、运行设置和工作目录；
- PathGuard 应用层沙箱、工具权限和审计；
- 事件 Envelope、Replay Store、SSE/WS 恢复；
- Memory、主动回想和后台整理；
- Diagnostic、Activity、Audit 三通道可观测性；
- Plugin Protocol、Plugin Runtime、SDK；
- Agent Skills 兼容、Bundle、绑定、安装和 turn snapshot；
- 临时 Subagent Runtime 和父子任务协议；
- Electron 桌面端原型以及 Web 运维/测试客户端。

尚未作为当前完成条件的能力：

- 完整对标 openhanako 的个人助理体验；
- 用户项目、任务、资料和日程的一体化工作台；
- 完整的 Bridge、多 Agent 团队和 DAG 编排；
- Agent 自己编写、测试和安装插件；
- Agent 的持续生活、长期自我成长和完整一生档案。

## 五、开发路线

产品路线使用 P 编号；仓库治理使用独立的 G 编号；历史平台建设 Phase 0-14 保留为实施证据，不再复用为当前产品阶段。

### G0：仓库治理与可复现交付

当前工作重点：

- GitHub Actions 覆盖文档治理、类型检查、测试、Web 构建、Desktop 构建和 Browser E2E；
- 固定 Node/npm 版本和依赖安装方式；
- 保持 main 可安装、可构建、可测试；
- 完成分支保护、依赖更新、发布、变更记录和公开协作流程；
- 建立文档事实归属、变更影响审计和例外机制。

### P1：个人助理基础体验

以 openhanako 为主要能力参考，建设：

- 记忆与人格的日常使用体验；
- 文件、工作目录、工具和安全审批；
- Skill、Plugin 和可迁移的 Agent 配置；
- 会话管理、后台任务、提醒和有限主动性；
- 面向普通用户的首次启动、模型配置、权限解释和错误恢复。

退出条件：OpenColorful 至少能够承担一个普通用户的日常个人助理工作。

### P2：个人效率工作台

- 项目、任务、状态、负责人、截止时间和关联资料；
- 日历视图、日程表、提醒和重复安排；
- 用户与 Agent 同级的工作区和清晰权限；
- 从项目发起 Agent 任务，结果回写项目和日程；
- 统一搜索、活动记录和可解释的自动化历史。

### P3：扩展生态与连接能力

- Plugin/Skill 市场和可信来源；
- 角色卡、Agent 配置和 Skill Bundle 的导入导出；
- 选择性接入 Telegram、飞书等外部平台；
- 多 Agent 协作、频道和更成熟的 Subagent 编排；
- 可替换的工作台模块和领域专用工作区。

### R1：Cordis 化与远期自进化

- Agent 生成插件和技能；
- 自动测试、审查、权限申请、安装和回滚；
- 能力变更的版本化、审计和用户确认；
- 更长期的主动生活、持续成长和 Agent 个人档案。

R1 属于远期研究路线，不作为当前版本的完成条件。

## 六、长期原则

1. **先有用，再自治**：先解决真实个人工作问题，再增加主动行为。
2. **用户始终在控制链上**：权限、安装、数据访问和能力变化必须可解释、可撤销。
3. **平台与形态分离**：Runtime、数据和安全边界属于平台；桌面、Web、Bridge 和领域工作区是不同消费端。
4. **能力可迁移**：Agent、Skill、Plugin、项目和日程数据应有清晰的导出、恢复和版本边界。
5. **远期愿景分阶段落地**：完整生活、自我成长和自扩展能力只能建立在稳定的产品、成本和安全基础上。
