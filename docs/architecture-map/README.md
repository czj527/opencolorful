# OpenColorful 架构地图

这里维护仓库的可交互架构地图。它的首要任务是帮助开发者用大白话理解：

- 项目分成哪些层；
- 一次对话或一次启动会经过哪些模块；
- 每个模块负责什么、不能越过什么边界；
- 当前项目正在做什么、什么已经合并但还不能宣称完成；
- 继续读代码时应该打开哪些真实文件。

## 打开地图

直接在浏览器打开 [`index.html`](index.html)，不需要启动开发服务器。

地图提供七种阅读方式：

1. **总览**：看系统分层和模块关系，不承担全部实现细节；
2. **怎么读**：用白话说明阅读顺序和开发判断问题；
3. **关键流程**：沿 Prompt、Wave B 分支、Memory、Plugin、Skill 或 Desktop 启动链路阅读；
4. **模块工作台**：单独摊开一个模块的职责、边界、协作对象、关键实现和代码覆盖；
5. **项目看板**：按现在要做、等待确认、下一步规划和已完成 / 已归档组织当前项目；
6. **边界规则**：查看项目最不能被悄悄破坏的约束和当前待闭环事项；
7. **源文件索引**：按模块检索生成器扫描到的生产源文件。

代码路径、包名和协议名保留原样，方便在编辑器里直接定位。模块说明、流程说明和规则说明
通过中文展示词典提供，避免把面向开发者的事实说明散落在页面脚本里。

## 维护合同

地图分成五层：

1. `architecture.manifest.json` 是架构事实来源，维护模块职责、所有权、不变量、关键流程、
   已知缺口和关键文件锚点；
2. `architecture.zh-CN.json` 是中文展示来源，按同一个模块 / 流程 / 规则 ID 提供面向人的
   说明。生成器会检查它是否和 manifest 的数量对齐；
3. `project-board.json` 是项目状态工作层，维护面向日常开发的卡片、验收清单、优先级、
   关联模块和原文入口。`docs/project-status.md`、对应计划和独立评估仍是状态事实权威；
4. `architecture.generated.js` 是生成文件，包含 manifest、中文展示层、项目看板、当前源文件清单、
   行数和扫描到的相对 import 证据，不能手工编辑；
5. `index.html`、`app.js`、`styles.css` 是展示层，应保持通用，不在里面复制项目事实。

新增或移动生产模块后：

```powershell
npm run architecture:map
npm run architecture:check
```

生成器会在以下情况失败：

- 生产源文件没有归属到任何架构节点；
- manifest 或流程引用的文件不存在；
- 项目看板引用的原文、架构模块或验收卡片结构不完整；
- 中文展示层缺少模块、流程、规则或待办事项的对应说明；
- 生成文件不是当前 manifest 和源文件扫描结果生成的内容。

仓库质量门已经接入 `architecture:check`。模块边界、不变量或产品语义变化时，必须在同一
个开发任务中同步更新 manifest、中文展示层和对应的权威架构文档 / Feature Spec。当前阶段、
交付门槛、验收清单或已知阻断变化时，还要同步更新 `project-board.json` 与状态来源。

这张地图是导航和理解工具，不替代 `docs/architecture.md`、`docs/memory-architecture.md`、
`docs/logging-architecture.md` 或当前 Feature Spec。
