# P1 切片 1.5：可用性攻坚（会话中心 IA / 设置页极简 / SSE 渲染性能）

**日期：2026-08-27**
**状态：待作者批准**
**前置：** P1 切片 1（`2026-08-26-p1-personal-assistant-slice.md`）代码已合并（PR #16-#23），本切片是作者真实后端初测后的可用性返修。

## 一、背景与证据

2026-08-27 作者首次用真实后端跑通对话与记忆，结论：**"达不到可用级别，5 天日用测试都难以流畅进行"**。三类问题经主 agent 代码级调查证实：

1. **设置页死控件 25 个**（审计：设置页 24 + 侧栏 1）。其中 9 个后端端点早已存在但前端未接线；3 个是本地显示偏好被误当后端功能；13 个概念错位或功能不存在（如"权限与安全"整页——工具权限是会话级 toolMode，不存在全局设置；"关于"页信息项渲染成可点击样式）。画了一屋子门，全是假的。
2. **SSE 流式渲染卡顿**。根因是级联放大：每 token = 1 条 SSE → 1 次主进程 IPC（`sse-proxy.cjs:105`）→ projector O(n) 全量重建消息数组（`projector.ts:86-101`）→ App.tsx 顶层 setState（`App.tsx:237-241`）→ 整棵树（侧栏/顶栏/Composer）跟着重渲染，无任何节流、memo 或虚拟化。
3. **IA 混乱**：左上角助理卡片语义不明——侧栏切换助理只过滤会话列表，新建会话却要再选一次助理，"当前助理"是半个概念。

另有两个环境级坑（同日排查发现）：后端未连接时桌面端**静默回退 mock**（作者一度以为在测真链路）；`supervisor start` 只起 supervisor 不拉起 agent server（期望态 stopped，看门狗正确地不启动它——需要显式 `POST /api/supervisor/start`，反直觉）。

## 二、决策记录

- **D1【已定 2026-08-27，作者拍板】会话中心 IA，去掉全局"当前助理"概念。** 参考 openhanako：侧栏会话列表不按助理过滤/分组，每个会话行用 badge（头像+名字）标识所属助理（`SessionList.tsx` AgentBadge 模式）；助理身份证卡从侧栏移至**会话头部**，展示当前会话所属助理、点击进档案页；新建会话默认归属"最近使用的助理"，空态在多助理时显示助理 chips（`WelcomeScreen.tsx` AgentChips 模式）。助理状态（运行中/空闲/离线）移到会话头部助理 chip 与顶栏连接态。
- **D2【已定 2026-08-27，作者拍板】设置页极简克制，对齐 Kimi web 心智：只满足基本需求。** 保留四个类目：外观（主题 + 减少动效）、模型与 Provider（现有已接线）、对话显示（显示思考事件 / 显示工具调用，localStorage 本地偏好）、关于（只读信息，改非可点击样式）。**删除**：通用/Agent/会话与工作区/记忆/Subagent/日志与诊断/插件与 Skills/权限与安全类目——Agent 与记忆编辑归档案页（T5 已有），会话级设置归会话内 UI（已有），无后端支撑的不保留尸体；被删但有真实后端价值的能力（Subagent 默认模型、诊断偏好、插件启停）记入 backlog 待有真实需求再立项。
- **D2a【已定 2026-08-27，作者澄清】极简不是目的，功能齐全 + 使用便捷才是。** 参考成熟项目（openhanako / Kimi web）的功能、入口与交互设计：基本功能不允许缺失（如发现"建不了第二个助理"这类窟窿要补）；设置与交互面向普通用户的便捷性设计，不堆砌专业化选项；被删类目中的能力若属基本功能，必须以合适入口保留（Agent/记忆编辑在档案页即是此原则的体现）。前端 UI 任务开工前先研究参考项目的对应交互，做详细设计，不凭空发明。
- **D3【已定】SSE 渲染性能修复四件套**：① ipc-source 事件入队 + 每帧/50ms 合批 notify（leading 首事件立即渲染保首字延迟，trailing 合批）；② projector 换 O(1) 索引（id→index Map + 最后一条 assistant 消息指针），消除每 token 全数组浅拷贝；③ MessageRow/EventRow 拆组件 + React.memo，回调 useCallback 稳定化；④ 聊天状态下沉出 App.tsx（或等效隔离），流式更新不再拖着侧栏/顶栏/Composer 重渲染。虚拟化（react-window 类）本切片不做，记 backlog（长会话再上）。
- **D4【已定】两个环境坑修复**：mock 模式在窗口顶部加醒目横幅（"当前为演示数据，后端未连接"）；`supervisor start` 的期望态改为拉起 agent server（消除 stopped 陷阱，看门狗语义不变）。
- **D5【已定】多助理创建入口补齐**：去掉侧栏切换器后，当前 UI 没有任何创建第二个助理的入口（T1 只覆盖首启）。在高级新建会话表单的助理选择器加"新建助理…"入口（复用 T1 的名字+底色模板表单）。

## 三、范围

**做：**

1. SSE 渲染性能（D3 四件套，desktop 前端）
2. 会话中心 IA 改造（D1 + D5）：侧栏去卡片/切换器、会话行 agent badge、会话头助理 chip（点击进档案页）、空态助理 chips、新建默认助理推导、`Thread` 增加 agentId 字段（`GET /api/sessions` 已支持跨助理列表，无需新端点）
3. 设置页极简重构（D2 四类目；对话显示过滤需在 ChatView 真正消费这两个本地偏好）
4. mock 醒目横幅（D4 前端）
5. supervisor start 自动拉起 agent server（D4 后端，含测试）

**不做（明确排除）：**

- 消息列表虚拟化、Markdown 渲染、IPC 层帧合批（先测①-④效果，不够再议）
- backlog：Subagent 默认模型设置、日志诊断偏好设置、插件启停 UI、检索层级、清除记忆、Subagent 运行上限/记录、侧栏外部变更 SSE 失效刷新（台账 #7）
- 切片 2 候选不动工（后台任务可见、mood 人格化、压缩可见）；openhanako 的活人感布局（mood/thinking 折叠块放消息流内、状态环放输入区边缘）仅记录为切片 2 设计素材

## 四、验收标准

1. **流畅度**：真实后端长回复（≥500 token）流式渲染主观无卡顿；render 频率从每 token 一次降到每帧一次（以代码审查 + React DevTools Profiler 或插桩计数为证据）。
2. **设置页零死控件**：设置页每个可见控件都有真实功能；被删类目在 UI 中无任何残留入口。
3. **IA 自洽**：侧栏无全局助理切换器；每个会话行能看到所属助理；会话头部能看到并进入当前会话助理的档案页；新建会话不再重复追问助理（默认最近使用，可改）。
4. **环境坑消除**：后端未连接时首屏即有醒目 mock 横幅；`supervisor start` 单命令后 agent server 自动 online。
5. **回归**：`npm run check` 全绿；desktop 构建绿；既有 I 组用例中不受 IA 变更影响的部分不失效（I7 身份证卡相关用例需按新 IA 改写）。
6. 以上通过后，作者继续执行 I 组真实验收 + 5 天日用。
