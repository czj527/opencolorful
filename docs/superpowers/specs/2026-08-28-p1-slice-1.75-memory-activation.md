# P1 切片 1.75：记忆激活（行为契约 / 工具引导 / 后台复盘 / 闭环实证）

**日期：2026-08-28**
**状态：已获作者批准（2026-08-28 对话拍板），实施中**
**前置：** P1 切片 1（PR #16-#23）与切片 1.5（PR #25-#30）已全部合并。本切片不修机制骨架，只解决"模型不会真的记"的行为层缺口。

## 一、背景与证据

2026-08-28 作者质疑："记忆系统是自己设计的、没有严谨工程化设计；hermes 能自行主动写记忆，一段时间未对话还会自动摘要。"代码级核查结论：

**骨架是生产验证的设计，不是拍脑袋**：热层四段传送带照抄 openhanako（`docs/memory-architecture.md` §三）；触发矩阵齐全（每 10 轮 / 会话结束 / 每日 03:00+空闲 30min / idle 入队，`memory-ticker.ts:299-307`）；`search_memory/remember/forget/pin_memory/unpin_memory` 五工具已接进真实会话链路（`src/server/routes/messages.ts:361`）；facts 表已有 `valid_until` + retention/activation 双强度 + status；20 个记忆测试文件覆盖各单元。

**真正的缺口在行为层（三处证据）**：

1. **记忆使用规则只有一行**（`memory-injection.ts:116-117`："当前对话中的信息和指令优先；如果对长期事实不确定，请调用 search_memory"）。openhanako 有四条行为契约（`references/openhanako/core/agent.ts:1244-1262`）：记忆是内化背景知识、用户不提就不主动翻、禁止说"我记得/你之前说过"、当前对话优先。我们的模型对"怎么用记忆"完全无约束。
2. **remember 工具 description 无 WHEN 引导**（`memory-tools.ts:172-173` 只说"记录一条待整理的事实意图"的机械语义）。hermes 在 schema description 里写明了时机与优先级（`references/hermes-agent/tools/memory_tool.py:1182-1192`）：用户偏好与纠正 > 环境事实 > 流程；SKIP 清单（琐碎/可重新发现/任务进度）；"流程归 skill 不归记忆"。
3. **没有"每轮后台复盘"机制**。hermes 的 `background_review.py` 是唯一低成本的"agent 自行判断该记什么"实现：每轮结束后重放对话快照，白名单工具只含记忆/技能写入，"Nothing to save" 是合法答案但不做默认。我们的主动写入完全依赖模型自发调 remember——没有任何机制驱动它，等于不会发生。

**闭环实证缺口**：现有测试全是单元/集成级（工具本身、整理流程、注入组装），"自发 remember → 每日整理审批 → 次日注入召回"这条行为链路从未端到端验证过。

**外部方案判定（2026-08-28 调研，证据见调研记录）**：mem0（图谱能力 2026.4 起云端独占）、supermemory（自托管=独立二进制+专有提取模型）、Zep/Graphiti（Python+Neo4j）均与"本地优先+单 SQLite+TS"形态冲突，**不引入**；可借鉴机制：mem0 v3 的 ADD-only+去重、Graphiti 的有效性窗口（我们 facts 表骨架已有）、MemoryBank 衰减（后置）。向量检索继续不上（openhanako v2 弃向量改标签+FTS5 CJK，与我们现有检索同路线）。

## 二、决策记录

- **D6【已定 2026-08-28，作者拍板】切片 1.75 范围收敛为四个任务**：记忆使用规则契约化、工具 WHEN 引导、后台复盘（hermes 轻量版）、行为级闭环实证。心跳巡检/cron/活人感（mood）留在切片 2 原定范围不动。
- **D7【已定】后台复盘的边界**：每轮 turn.completed 后一次工具型 LLM 调用（复用 `completeText` utility 通道，走 per-agent utilityModel 设置），产出结构化 JSON intents 追加到 `memory_journal`（actor 新增 `background_review`），**不直写长期库**——整理审批仍由既有记忆 Agent + MemoryPolicy 负责。复盘失败/LLM 不可用走降级，绝不阻塞主对话。
- **D8【已定】复盘开关归 per-agent 记忆设置**：`MemoryAgentSettings` 新增 `reviewEnabled`（默认 true），档案页记忆设置区加 toggle（功能入口已有归属，不回设置页）。
- **D9【已定】复盘去重靠提示词+审批双层**：复盘输入带当前 pinned/memory.md 快照与最近待处理 intents（防重复提案）；整理时记忆 Agent 审批去重兜底。不做写入期哈希去重（mem0 v3 思路记 backlog，待证据表明重复率真的高再做）。

## 三、范围

**做：**

1. **T12 记忆使用规则契约化**：`memory-injection.ts` 一行规则 → openhanako 四条契约（内化背景知识 / 用户不提不主动翻 / 禁止"我记得"类表述 / 当前对话优先），注入预算内优先保留规则段（现状已是）。
2. **T13 工具 WHEN 引导**：`memory-tools.ts` 的 remember/forget/search_memory description 写清时机、优先级（用户偏好纠正 > 环境事实 > 约定）、SKIP 清单、remember 结果的"待整理"语义（已记录≠已记住，整理窗口才生效）。
3. **T14 后台复盘服务**：新增 `src/runtime/memory/background-review.ts`（订阅 turn.completed → per-agent 串行 tail → 读会话快照 → completeText → 解析 JSON intents → appendIntent）；journal actor 枚举加 `background_review`；`MemoryAgentSettings.reviewEnabled` + 档案页 toggle；观测走既有 instrument 生命周期（`memory.review.*`）。
4. **T15 行为级闭环实证**：集成测试编排"复盘产出 intent → 每日整理审批 → 次日注入"全链路（scripted completeText，不发真实网络请求）；断言每一步的中间态而非只断言终态。

**不做（明确排除）：**

- 向量检索、知识图谱、遗忘曲线衰减（backlog，待真实证据）
- 心跳巡检/cron/mood/notify（切片 2）
- 复盘的技能维度（hermes 复盘同时维护 skills；我们 skills 的 curator 化属远期，本次只取记忆维度）
- mem0/supermemory/Zep 等外部记忆服务接入

## 四、验收标准

1. **契约生效**：新会话 system prompt 注入四条记忆使用规则（单测断言注入块内容）；remember/search_memory 的 description 含 WHEN 与 SKIP（单测断言）。
2. **复盘真实运行**：开启 reviewEnabled 的助理对话产生 turn.completed 后，复盘服务在后台完成一次 LLM 调用并按结果追加 journal intent（集成测试：scripted completeText 返回一条 intent → journal 可见 actor=background_review 的记录；返回空 → 无写入）。reviewEnabled=false 时无任何调用。LLM 不可用时降级静默，主对话无感知。
3. **闭环链路**：T15 测试从 intent 走到注入全绿。
4. **回归**：`npm run check` 全绿；web Playwright 不受影响（不动 web）；desktop 构建绿。
5. 以上通过后合并，作者真实日用观察 remember/复盘的实际触发率与记忆质量，作为切片 2 记忆方向（衰减/有效性窗口/向量）的立项依据。
