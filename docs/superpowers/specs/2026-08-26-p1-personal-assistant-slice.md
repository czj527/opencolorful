# P1 切片 1：可用的桌面个人助理（Feature Spec）

> 日期：2026-08-26 | 状态：已立项
> 上游：`docs/positioning-and-roadmap.md` §五 P1；治理约束：`plans/g1-repo-convergence.md`（G1.1 前端收敛、G1.5 平台冻结）
> 执行依赖：`plans/desktop-parity.md` D 波次（已并入 P1 轨道）

## 一、用户问题

本项目的第一个用户是作者本人。当前现状是：平台能力齐备（记忆、工具、沙箱、插件、Skills、Subagent、日志），但**没有一个能每天打开用的桌面助理**：

- 桌面端刚完成真实数据对接，仍是极简原型，首次上手无路——没有引导，不知道先建助理、先配模型；
- 助理没有"存在感"：人格注入在服务端生效，但 UI 上看不到"它是谁"；记忆在后台运转，但用户感知不到"它记得我"；
- 出错时是死路：模型未配置、会话忙、断线等场景缺少面向普通用户的可读提示和下一步动作。

对比 openhanako 的差距诊断见 G1 计划 §一。本切片不追求功能数量，追求**第一个真实用户能日用**。

## 二、目标（本切片范围）

一个普通用户从启动到日常使用的最小完整闭环：

1. **首次启动引导（onboarding）**：创建第一个助理（名称 + 底色模板）、配置第一个 Provider 与模型、选择默认工作目录、用一页白话解释工具权限模式；引导完成后直接进入与助理的第一次对话。空态下各页面给出通往引导的入口，而不是空白。
2. **桌面对话主干补齐**：D1b 波次内容——完整新建会话表单（title/cwd/agent/toolMode/thinking/model/workspace，对齐 web session-new）+ Electron 原生目录选择对话框。
3. **助理人格可见**：侧栏助理名片与会话头呈现名称、底色描述和运行状态（数据均已有，纯呈现层）。
4. **记忆日用可感知**：对话中助理能记住经确认的信息（现有回想链路，不改机制）；记忆页补齐 pinned 管理与记忆设置入口，用户能查看、钉住、纠正。
5. **出错可恢复**：Provider 未配置/凭据失效、会话忙（409）、断线重连等场景给中文可读提示与下一步动作；错误不再以英文原文或静默失败呈现。

## 三、非目标（本切片明确不做）

- 提醒、笺、心跳等主动行为（P1 切片 2 候选）；
- 插件中心、Skills 目录桌面化（D4/D5，P1 后半评估）；
- IM 渠道、多端实时同步、多 Agent 协作；
- 安装包签名、公证、自动更新等发布工程（另行发布计划）；
- 任何新平台层抽象、新契约面、新存储层（G1.5 冻结纪律）；
- web/ 新增任何产品功能（G1.1 冻结）。

## 四、约束

- Server-first、凭据不出主进程、renderer 只消费 DesktopDataSource 接口（`plans/desktop-wiring.md` 架构决策不变）；
- 不引入 `package.json` 之外的新运行时依赖；UI 延续现有极简方向与亮暗双主题；
- 记忆机制以 `docs/memory-architecture.md` 为准，本切片只做呈现与纠正入口，不改整理管线；
- 每个用户可感知功能完成后补 `plans/desktop-e2e-test-plan.md` 用例并真实后端验收。

## 五、验收标准

- 干净 `OPENCOLORFUL_HOME` 下，新用户从启动到发出第一条消息并收到流式回复，全程不超过 5 分钟，无需阅读源码或文档；
- 助理在后续会话中能想起引导与早前对话中确认过的信息（回想链路真实命中，非 mock）；
- 引导、对话、记忆、设置路径上无英文报错原文、无静默失败，每个失败态给出下一步动作；
- **作者本人真实日用 ≥ 5 天**（本切片最重要的验收项）；日用中暴露的问题记录进实施计划，作为切片 2 输入；
- `npm run check` 全绿；desktop 真实后端手工验收通过（沿用 `plans/desktop-e2e-test-plan.md` 增补用例）。

## 六、实施关系

- 本 spec 落地为 P1 实施计划（`plans/p1-personal-assistant.en.md`，A 类英文权威，产品决策措辞以本中文 spec 为准），负责任务拆分、文件归属与波次调度；
- D 波次中与本切片重叠的条目（D1b 等）按 P1 优先级调度；D2-D7 其余波次在切片 1 验收后继续；
- 切片 2（提醒与有限主动性）在本切片验收后立项，需新 Feature Spec。
